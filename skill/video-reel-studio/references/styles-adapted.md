# ستايلات مقتبسة — ليه نقلنا الاتجاه مش الكود

## السؤال الأول: هل Lemo محتاج Claude؟

| الجزء | محتاج Claude؟ | الدليل |
|---|---|---|
| **التثبيت** (`claude plugin marketplace add …`) | **أيوه** — الأمر ده بتاع Claude Code | README، قسم Install |
| **محتوى السكل** (`plugin/skills/lemo-opuscar/`) | **لأ** — README نفسه بيقول: «For other agents, copy `plugin/skills/lemo-opuscar/` into their skills folder» | README |
| **المحرّك** (Node 20+, ffmpeg 7+, Python 3.11+) | **لأ** — أدوات محلية | README، Before you start |
| **جودة الستايل** | **جزئيًا** — الستايلات مضبوطة على Opus 5.5، والمؤلف بيحذّر إن موديلات تانية ممكن ما تعيدهاش بنفس الجودة | README، تنبيه «Built for Claude» |
| **الأفلام التجريبية** | **مش ملكنا** — CC BY 4.0 مع نسبة لـLemoLab | Licence |

**الخلاصة:** اللي محتاج Claude هو *التغليف* وتجربة الجودة، مش المنطق. ينفع نستخدمه من OpenCode،
بس إحنا مش محتاجين نعمل ده — إحنا عندنا محرّك مختلف (canvas + `motion/` + الـ17 ستايل بتوعنا)،
فنقل الستايلات كاملة كان هيبقى نسخ محرّك تاني مش استفادة.

## السؤال التاني: ليه ما ننقلش Awesome؟

لأنهم **مش برنامج**. `athemeroy` أبحاث + لينكات (CC BY 4.0)، و`clonn` كتالوج Markdown (MIT).
«النقل» معناه إعادة نشر محتوى، مش تشغيل. الصح إننا **نقتبس بالأتريبوت**، أو نضيف كارت عندهم،
مش نعمل نسخة تالتة من نفس القائمة. عشان كده `docs/ecosystem.md` بيوصّف الأربعة ويشرح الفرق،
ومافيهوش أي محتوى منسوخ.

## اللي عملناه بدلًا من كده: حزمة ستايلات بصيغة محرّكنا

`styles/pack.json` — **10 ستايلات** مستوحاة من كتالوج Lemo، وكل واحد **مكتوب من الأول**
لصيغة محرّكنا: لوحة، خطين، أفعال حركة، صوت، و3 مشاهد جاهزة للصياغة.

| id | الاسم | إمتى |
|---|---|---|
| `watercolor` | ألوان مائية | قصة/مكان/إحساس |
| `swiss-grid` | الشبكة السويسرية | إعلان فكرة/مقارنة/رقم |
| `blueprint` | مخطط هندسي | شرح نظام أو آلة |
| `paper-cut` | قصاصات ورق | قصة بسيطة/تعليم |
| `ascii-crt` | شاشة قديمة | محتوى تقني/terminal |
| `isometric` | أيزومتري | شرح منتج/رحلة |
| `newsreel` | أرشيف خمسينات | حكاية تاريخية/مصدر |
| `chalkboard` | سبورة | درس/تفسير |
| `data-story` | حكاية رقم | إحصائية/مقارنة |
| `risograph` | طباعة ريزو | طاقة/ثقافة |

```bash
python scripts/style_pack.py list
python scripts/style_pack.py show blueprint
python scripts/style_pack.py apply "<work>" blueprint   # يكتب style.json
```

### الفرق بين `style.json` و`theme.json`

| | `theme.json` | `style.json` |
|---|---|---|
| مين بيملكه | العميل (براند) | المشروع (اتجاه فني) |
| بيحكم | الألوان، الخط، الكابشن | الحركة، الملمس، الإيقاع، شكل المشهد |
| لو اتعارضا | **البراند يكسب في اللون** | الستايل يكسب في الحركة |

السكربت بيكتب `style.json` لوحده، ومابيمسّش `theme.json` — عشان ما نكسرش هوية عميل موجود.

## الحدود القانونية (مهمة)

- **مافيش فيلم أو فريم أو `STYLE.md` منقول** من Lemo. الملف ده و`pack.json` مكتوبين بصياغتنا.
- وصف الستايلات في `docs/ecosystem.md` **إشارة ونقد**، مش إعادة نشر.
- أي اقتباس من فيلم ليهم (CC BY 4.0) لازم كريدت **LemoLab** + لينك + بيان التعديل.
- كودهم MIT: لو يوم من الأيام استخدمنا سطر منه، يتكتب في `THIRD_PARTY.md`.

## لو عايز ستايلات أكتر

الحزمة دي **بداية مش سقف**. إضافة ستايل = كائن جديد في `pack.json` بنفس الحقول الخمسة
(لوحة، خط، حركة، صوت، مشاهد). ما تحتاجش كود جديد ولا تعديل في السكربت.
